📡 API 参数（2.1）

temperature 温度
控制输出概率分布的「尖锐程度」。越低越确定稳定，越高越多样随机
代码/结构化输出 → 调低；创意写作 → 调高。与 top_p 二选一调整，别同时动
top_p 核采样
控制候选 Token 的采样「范围」（概率累计前 p 的候选）
易混点：temperature 管分布形状，top_p 管候选范围——A 选项常说反
max_tokens 最大生成Token
安全阀：到上限立即停止，可能在句子中间截断
想要简短完整回答 → 用提示词引导，max_tokens 只做兜底防成本失控
messages 消息列表
多轮对话的关键：保存完整历史（system/user/assistant）
每轮把全部历史重新喂入，模型才知道上下文
stream 流式输出
逐Token返回结果，降低首字等待时间
用户体验优化，与生成质量无关

📚 RAG 检索增强（2.2 / 2.5）

Chunk 文本分段
索引第一步之后把文档切成小块，便于检索
分段过大→检索不精准；过小→上下文不足
Embedding 向量化
把文本转成数字向量，语义相近的向量距离近
对比学习训练：相关文本拉近、无关推远；好模型可跨词汇匹配语义
余弦相似度
检索时衡量问题向量与chunk向量的相似程度
向量检索的标准相似度度量
问题改写 Condense Question
多轮对话中先结合历史改写问题（补全指代）再检索
「他的主管是谁」→「张三的主管是谁」，否则召错内容
Rerank 重排序
对初步召回的文档二次精排，把最相关的排前面
Recall 靠召回兜底，Precision 靠重排提升

📏 评测指标（2.4 / 3.6）— 必考重灾区

Context Recall 上下文召回率
该找的文档「找到没有」——正确答案所在chunk是否被召回
漏召 = Recall 问题 → 加大k值/改分段
Context Precision 上下文精确率
找到的文档「排前没有」——相关chunk是否排在靠前位置
召回了但排第4名 = Precision 问题 → 加重排
Answer Relevancy 答案相关性
答案与问题的相关程度
答非所问 → 查这
Answer Correctness 答案正确性
最终答案与标准答案的一致性
内容错了 → 查这
Retrieval Quality 检索质量
Recall + Precision 的综合：找得全 + 排得好
口诀：先看在不在（Recall），再看靠不靠前（Precision）
Task + Metric 端到端评测
任务+指标的评测框架，量化「感觉还行」
感觉的三大缺陷：难量化、缺标准、无法复现回归
白盒化评测
检查工具调用序列等中间执行过程
Agent错误常在过程：工具路径错、Token超支、中间格式崩

✍️ Prompt 工程（2.3）

CoT 思维链
让模型逐步推导中间步骤，分解复杂问题提升推理表现
经典案例：差旅费计算，普通提示算错，CoT算对
Few-shot 少样本示例
在提示词中给示例，明确抽象要求
描述太抽象时加示例；推理模型（Qwen3）无需写'一步一步推理'
AI Judge 提示词裁判
用模型自动评判提示词优化效果
必须同时监控训练集+评估集准确率，防过拟合

🤖 Agent（3.x）

Function Calling 工具调用
模型识别意图并输出结构化调用请求的能力
是模型原生能力；MCP 是接入协议层，不互相替代
MCP 模型上下文协议
标准协议让Agent动态发现和调用工具，工具即插即用
新增工具不改Agent代码，降低集成维护成本
Plan & Execute 规划执行
Agent先自主规划再执行，动态应对工具失败等异常
vs 固定工作流：工作流遇异常卡死，P&E能自主调整（治本 vs 打补丁）
多Agent协作模式
分层规划（Leader分派，适合有依赖链的任务）/ 共创协作
大纲→代码→文稿这类顺序依赖 → 分层规划
短期记忆 / 长期记忆
短期=当前对话上下文窗口；长期=向量化持久存储按需检索
截断保最近N轮的坑：早期偏好（风格要求）被遗忘
Skill 技能
把专家经验固化为结构化指令，Agent识别任务自动加载
五步法第一步最关键：裸跑建基线，否则无法证明改进
Harness Engineering 挽具工程
为Agent配标准、验证、记录、停止条件的支撑环境
截图验证=客观证据；四要素：标准/Skill/验证/日志停止条件
Loop Engineering 迭代闭环
标准→Skill→样本→截图验证→问题记录→写回规则→新主题验证
同类错误重复出现 → 写回Skill/验证器，不是只改当前作品
上下文75%操作
运行 /compress 压缩历史保留关键信息
梯度：compress=保信息续工作，clear=全清重来

🔧 微调与蒸馏（4.1）

LoRA 低秩自适应
挂载低秩矩阵学ΔW，只训约0.4%参数，原权重不动
三板斧：低秩挂载 / 0.4%参数 / 防灾难性遗忘（保留97%基础能力）
灾难性遗忘
微调覆盖原能力，学了新的忘了旧的
LoRA 原权重冻结 = 天然防御
白盒蒸馏 KD
学生学习教师输出每个token的概率分布（软标签）
软标签含暗知识（HR 70%/行政25%），精度高但需教师权重；黑盒只需API
数据合成质量过滤
只查结果schema：JSON可解析、字段齐全、取值合法
口诀：查结果不查过程（推理过程合理性不检查）
过拟合信号
训练损失持续下降，验证损失先降后升
药方：减轮次（num_train_epochs）或加数据
蒸馏合规
部分商业模型条款禁止用其输出训练竞品
解法：Apache 2.0 开源模型（Qwen）当教师
